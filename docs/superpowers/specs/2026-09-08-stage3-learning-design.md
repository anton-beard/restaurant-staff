# Этап 3: курсы, уроки, тесты. Дизайн

Дата: 2026-09-08. Статус: согласован с владельцем проекта. Уточняет разделы 3, 4 (обучение и тесты) и 10.3 общего спека `2026-09-07-restaurant-staff-design.md`.

## 1. Цель и рамки

Владелец создаёт курсы по должностям (уроки с текстом, картинками и ссылками на видео плюс итоговый тест) и отдельные тесты по расписанию. Сотрудники проходят уроки и тесты в боте, владелец видит прогресс и попытки в админке.

Входит: курсы и уроки, вопросы с одним правильным ответом, автоназначение по должностям («всем текущим» или «только новым»), тесты по расписанию и разовой рассылкой, прохождение в боте с сохранением состояния в базе, неограниченные пересдачи, напоминания и просрочки, экран прогресса в админке, рефакторинг маршрутизации состояний бота.

Не входит: несколько правильных ответов и свободные ответы, загрузка видео на сервер, Mini App, рейтинг и карточка сотрудника (этап 4).

Тестовые данные: курс «Эспрессо по стандарту» (должность Бариста) с уроками «Помол и дозировка», «Экстракция», «Молоко» и вопросами вроде «Сколько секунд длится экстракция?», «Температура молока для капучино?»; отдельный тест «Меню недели» для всех должностей по понедельникам в 10:00 со сроком 8 часов.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Содержимое урока | Текст с абзацами, картинки (загрузка в админке), ссылки на видео (YouTube и т.п.), файлы видео не храним |
| Тип вопросов | Один правильный из 2–5 вариантов |
| Назначение курса | По должностям; при публикации выбор «всем текущим» или «только новым»; новым сотрудникам и при смене должности автоматически |
| Провал и просрочка | Пересдачи без ограничений, все попытки видны; просрочка уведомляет, курс остаётся открытым |
| Тесты по расписанию | По дням недели и времени (без интервалов) + срок в часах; разовая рассылка кнопкой |
| Состояние прохождения | В базе (незавершённая попытка теста, текущий урок), не в памяти бота |

## 3. Модель данных (миграция `003_learning`)

- **courses**: id, title, description, due_days (int > 0), pass_score (0..100, по умолчанию 80), status (`draft` | `published` | `archived`), published_at, assign_existing (0/1: при публикации назначить текущим сотрудникам), created_at. **course_positions** (course_id, position_id, PK).
- **lessons**: id, course_id (cascade), position (1..n), title, body (текст), media (json: массив `{ kind: 'image', path }` | `{ kind: 'video', url }`).
- **quizzes**: id, title, course_id (null для отдельного; cascade при удалении курса), pass_score, schedule (json weekly или null), deadline_minutes (для отдельных; null для курсовых), status (`draft` | `published` | `archived`), next_run_at, created_at. **quiz_positions** (quiz_id, position_id, PK; для курсовых тестов пусто, используются должности курса).
- **questions**: id, quiz_id (cascade), position, text, options (json-массив строк, 2..5), correct_index (0..4).
- **course_assignments**: id, course_id, employee_id, assigned_at, due_at, current_lesson (int, начинается с 1), status (`in_progress` | `completed` | `overdue`), completed_at, reminder_sent_at. Уникальный (course_id, employee_id).
- **quiz_assignments**: id, quiz_id, employee_id, course_assignment_id (null для отдельных), slot_at, assigned_at, due_at, status (`pending` | `passed` | `overdue`), passed_at, reminder_sent_at. Уникальный (quiz_id, employee_id, slot_at).
- **quiz_attempts**: id, assignment_id, started_at, finished_at (null пока идёт), current_question (int, с 1), answers (json-массив индексов по порядку вопросов), score (0..100), passed (0/1). Не больше одной незавершённой попытки на назначение (проверяется в коде).
- Картинки уроков лежат в `DATA_DIR/uploads/lessons/<course_id>/<file>`, отдаются через существующий `/api/uploads/*` (только владельцу) и боту напрямую с диска. Чистке по сроку не подлежат.

Переходы: курс `in_progress` → после кнопки «Дальше» на последнем уроке создаётся `quiz_assignment` итогового теста (`slot_at` = момент завершения уроков, `due_at` = `due_at` курса) → попытка сдана → назначение теста `passed`, курс `completed`. Провал: попытка `finished_at` заполнен, `passed = 0`, назначение остаётся `pending`, новая попытка по кнопке. Просрочка по `due_at` переводит `in_progress`/`pending` в `overdue`; завершение после просрочки переводит в `completed`/`passed`.

Балл: `round(правильных / всего * 100)`, сдано при `score >= pass_score`.

## 4. Бот

### 4.1 Маршрутизатор состояний (рефакторинг)

`bot/states.ts`: middleware читает `bot_states` один раз на апдейт в `ctx.state` (типизированное объединение `{ kind: 'collecting_photos' … } | { kind: 'reject_comment' … } | { kind: 'quiz'; attempt_id }` | null) и роль в `ctx.role` через `roleOf`. Регистрация обработчиков состояния: `onState(bot, 'collecting_photos', handler)` — срабатывает только при совпадении `kind`, иначе пропускает дальше. Модули `tasks.ts` и `review.ts` переводятся на него без изменения поведения; тесты этапа 2 остаются зелёными. Порядок регистрации: linking → состояния → тематические обработчики (tasks, review, learning) → fallback.

### 4.2 «Обучение»

Список назначений курсов сотрудника в статусах `in_progress`/`overdue`: «<название>, урок N из M, до <срок>» с кнопкой «Продолжить» (`course:continue:<assignment_id>`), и завершённые одной строкой «Пройдено: …». Пусто: «Курсов нет».

«Продолжить»: бот отправляет урок `current_lesson`: заголовок и текст одним сообщением, затем каждую картинку (`sendPhoto` с файла) и каждую ссылку на видео отдельным сообщением, в конце кнопка «Прочитал, дальше» (`course:next:<assignment_id>:<lesson_position>`). Нажатие с несовпадающим номером урока игнорируется (защита от двойного нажатия). После последнего урока: создаётся `quiz_assignment` итогового теста (идемпотентно по уникальному индексу), сообщение «Уроки пройдены, остался тест» с кнопкой «Пройти тест» (`quiz:start:<quiz_assignment_id>`).

### 4.3 «Тесты»

Список назначений тестов в статусах `pending`/`overdue`: «<название>, до <срок>» с кнопкой «Начать» или «Продолжить» (если есть незавершённая попытка) → `quiz:start:<assignment_id>`. Пусто: «Тестов нет».

`quiz:start`: если есть незавершённая попытка, продолжаем с `current_question`; иначе создаём попытку. Состояние `{ kind: 'quiz', attempt_id }` ставится в `bot_states`. Вопрос отправляется текстом «Вопрос N из M: …» с вариантами инлайн-кнопками `quiz:answer:<attempt_id>:<question_position>:<option_index>`. Ответ с `question_position !== current_question` игнорируется (всплывающее «Уже отвечено»). После последнего ответа: попытка завершается, балл считается, сообщение «Сдано, N из 100» (назначение `passed`, если курсовой тест — курс `completed`, уведомление владельцу «<сотрудник> прошёл курс <курс>») или «Не сдано: правильных K из M, нужно X%» с кнопкой «Пересдать» (`quiz:start:<assignment_id>`), владельцу уведомление о провале. Состояние снимается.

Любое сообщение в состоянии `quiz` кроме ответа: «Идёт тест, ответьте на вопрос N» и повтор вопроса.

### 4.4 Уведомления

Сотруднику: «Новый курс: …, срок до …» (кнопка «Продолжить»), «Новый тест: …, до …» (кнопка «Начать»), напоминания, просрочка. Владельцу: завершение курса, провал теста, просрочка курса/теста. Все через `Notifier`.

## 5. Назначения и планировщик

- **Публикация курса** (API `POST /api/learning/courses/:id/publish` с `{ assign_existing: boolean }`): проверка «есть уроки и итоговый тест с вопросом», статус `published`, `published_at = now`, `assign_existing` сохраняется. При `assign_existing` сразу создаются назначения активным сотрудникам должностей курса, уведомления.
- **Шаг `assignCourses`** (планировщик, раз в минуту): для каждого опубликованного курса и каждого активного сотрудника его должностей без назначения: если `assign_existing` или сотрудник привязался/сменил должность после `published_at`, создать назначение. Для этого у сотрудника добавляется `position_changed_at` (миграция: `alter table employees add column position_changed_at`; заполняется при смене должности и при привязке Telegram). Условие «после публикации» сравнивает `max(linked_at, position_changed_at)` с `published_at`; `linked_at` = момент `linkTelegram` (новая колонка). Существующим сотрудникам колонки проставляются миграцией значением `created_at`.
- **Шаг `issueDueQuizzes`**: опубликованные отдельные тесты с `next_run_at <= now`; слот старше 60 минут пропускается; назначение каждому активному сотруднику должностей теста, `due_at = slot + deadline_minutes`; `next_run_at` сдвигается через `nextRun`. Разовая рассылка: `POST /api/learning/quizzes/:id/issue` создаёт назначения со `slot_at = now`.
- **Шаг `learningReminders`**: курсы за 24 часа до `due_at` (если общий срок больше 48 часов, иначе за половину), тесты за половину срока; один раз, `reminder_sent_at`.
- **Шаг `learningOverdue`**: `in_progress`/`pending` с `due_at < now` → `overdue`, уведомления.
- Все шаги идемпотентны за счёт уникальных индексов и `reminder_sent_at`; ошибки шага изолированы, как в этапе 2.

## 6. Админка

Меню «Обучение» с тремя подразделами.

- **Курсы**: таблица (название, должности, уроков, статус, назначено / завершено). Форма: название, описание, должности, срок в днях, проходной балл; уроки списком с перемещением вверх/вниз (заголовок, текст, картинки через загрузку `POST /api/learning/upload` → путь, ссылки на видео); итоговый тест: вопросы (текст, 2–5 вариантов, радио правильного). Сохранение черновика без ограничений; «Опубликовать» открывает выбор «всем текущим / только новым» и валидирует состав; «В архив» останавливает назначения, существующие назначения не трогает. Редактирование опубликованного курса разрешено (правки видят те, кто ещё не дошёл до урока).
- **Тесты**: отдельные тесты: название, должности, вопросы, проходной балл, расписание (дни недели и время) или без, срок в минутах; «Опубликовать», «Выдать сейчас», «В архив».
- **Прогресс**: таблица назначений (курсы и тесты) с фильтрами по сотруднику, курсу/тесту, статусу; строка раскрывается в попытки (дата, балл, сдано).

API под `/api/learning/*`, все за сессией владельца: `courses` CRUD + `publish` + `archive`; `quizzes` CRUD + `publish` + `issue` + `archive`; `assignments` список с фильтрами и `attempts` по назначению; `upload` картинок (jpg/png/webp до 5 МБ).

## 7. Тестирование

- Репозитории и переходы на in-memory SQLite: назначение, завершение уроков, попытки, подсчёт балла, `passed`/`completed`, идемпотентность.
- Бот через `handleUpdate`: список курсов, урок с медиа, «Дальше» с защитой от повтора, создание теста после последнего урока, прохождение вопрос за вопросом, игнор повторного ответа, провал → пересдача → сдача, «Продолжить» незавершённой попытки, сообщение во время теста.
- Маршрутизатор: тесты этапа 2 без изменений плюс тест, что состояние читается один раз и обработчики других `kind` не срабатывают.
- Планировщик: «всем текущим» и «только новым» (старый сотрудник не получает), смена должности, расписание тестов, пропуск старого слота, напоминания, просрочки.
- API через inject: CRUD, публикация с валидацией, выдача, загрузка картинки, прогресс.
- Сквозной: публикация курса → назначение → уроки → тест → владельцу «прошёл курс».
- Ручной прогон: реальный бот, один курс с картинкой и ссылкой на видео, один тест по расписанию.
