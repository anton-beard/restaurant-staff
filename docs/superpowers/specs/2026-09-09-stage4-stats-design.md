# Этап 4: сводка, рейтинг, карточка сотрудника. Дизайн

Дата: 2026-09-09. Статус: согласован с владельцем проекта. Закрывает разделы 4 («Мой рейтинг»), 6 (сводка, карточка сотрудника) и 10.4 общего спека `2026-09-07-restaurant-staff-design.md`.

## 1. Цель и рамки

Владелец видит, как работает команда: сводку за сегодня и неделю, рейтинг сотрудников за период, карточку каждого сотрудника с историей. Сотрудник видит свой балл и место. По понедельникам владелец получает недельный дайджест в боте.

Входит: расчёт метрик на лету, страница «Сводка» (стартовая), карточка сотрудника, API статистики, «Мой рейтинг» в боте, расширенная «Сводка» в боте, недельный дайджест с настраиваемым временем, индексы под запросы.

Не входит: графики по дням, экспорт, ежедневный дайджест, изменения в логике заданий и обучения.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Формула балла | `round(0.6 × доля заданий в срок × 100 + 0.4 × средний балл тестов)`; при отсутствии одного слагаемого второе с весом 100%; без обоих: «нет данных», вне рейтинга |
| Что видит сотрудник | Свои цифры за 30 дней и место среди коллег |
| Регулярная сводка | Недельная по понедельникам, время настраивается (по умолчанию 09:00) |
| Хранение | Без таблиц статистики, расчёт SQL-запросами по факту |

## 3. Метрики (`server/stats/`)

Период `[from, to)` в ISO UTC; в админке 7 / 30 / 90 дней назад от `now`, в боте 30.

- **Задания сотрудника**: экземпляры `task_instances` с `employee_id = ?` и `due_at` в периоде и статусом `accepted` или `overdue`. `total` = их число; `onTime` = `accepted` с `completed_at <= due_at`; `late` = `accepted` с `completed_at > due_at` (принято после срока, например владельцем); `overdue` = статус `overdue`. `onTimeShare = onTime / total` (null при `total = 0`). Незавершённые (`pending`, `submitted`, `review`, `open`) не считаются.
- **Тесты сотрудника**: по каждому назначению `quiz_assignments` сотрудника берётся последняя завершённая попытка (`finished_at` не null, максимальный `id`) с `finished_at` в периоде; `avgQuiz` = среднее `score` по таким попыткам (null, если их нет); `quizzesPassed` / `quizzesFailed` по `passed` последней попытки.
- **Балл**: см. таблицу решений; `score` null при отсутствии обоих слагаемых.
- **Рейтинг**: активные сотрудники (`status = 'active'`), отсортированные по `score desc, onTimeShare desc, full_name`; сотрудники с `score = null` в конце с пометкой «нет данных» и без места; одинаковые баллы получают одно место (следующее место = позиция).
- **Сводка владельца** (`summary`): для «сегодня» (с 00:00 локального дня по `TZ`) и «7 дней»: `issued` (экземпляры с `issued_at` в периоде), `onTime`, `late`, `overdue` (как выше, но по всем сотрудникам и `due_at` в периоде), `awaitingAi` (сдачи `ai_status = pending`), `awaitingOwner` (сдачи `decision = needs_review`); обучение: `coursesInProgress`, `coursesOverdue` (текущие), `quizzesPassed`, `quizzesFailed` (за период по последним попыткам).
- **Карточка сотрудника** (`employeeStats`): метрики за период плюс списки: задания за период (название, срок, статус, `completed_at`, оценка ИИ последней сдачи), назначения курсов (все, с уроком и статусом), назначения тестов с попытками (дата, балл, сдано).
- **Индексы** (миграция `004_stats`): `task_instances(employee_id, due_at)`, `task_instances(issued_at)`, `quiz_attempts(assignment_id, finished_at)`, `course_assignments(employee_id)`, `quiz_assignments(employee_id)`.

Все функции чистые относительно `db` и `now`, тестируются на in-memory SQLite.

## 4. Админка

- **Сводка** — маршрут `/`, стартовая страница вместо редиректа на задания. Переключатель периода рейтинга 7 / 30 / 90. Блоки: «Сегодня» и «7 дней» (выдано / в срок / поздно / просрочено), «Ждёт проверки» (ИИ / владелец, ссылка на очередь), «Обучение» (курсов в процессе / просрочено, тестов сдано / провалено за 7 дней), таблица рейтинга (место, сотрудник, должность, балл, в срок X из Y, средний балл тестов, просрочек; строки с просрочками подсвечены; клик открывает карточку). Настройка времени недельного дайджеста: поле «Недельная сводка по понедельникам в ЧЧ:ММ» с сохранением.
- **Карточка сотрудника** `/employees/:id`: имя, должность, статус, привязка Telegram; метрики за период (переключатель); вкладки «Задания», «Курсы», «Тесты». В таблице сотрудников имя становится ссылкой на карточку.
- **API** (за сессией владельца): `GET /api/stats/summary` → `{ today, week, queue: { awaitingAi, awaitingOwner }, learning }`; `GET /api/stats/rating?days=7|30|90` → `RatingRow[]`; `GET /api/stats/employees/:id?days=` → `{ employee, metrics, tasks, courses, quizzes }`; `GET /api/settings/digest` и `PUT /api/settings/digest { time: 'HH:MM' }`.

## 5. Бот

- «Мой рейтинг» (сотрудник): за 30 дней «Балл: N», «Заданий в срок: X из Y» (или «Заданий пока не было»), «Тесты: средний балл Z» (или «Тестов пока не было»), «Место: K из M» (M = сотрудники с баллом; при `score = null` строка «Пока нет данных для рейтинга»).
- «Сводка» (владелец): существующие строки плюс «Сегодня: выдано A, в срок B, просрочено C» и «Топ за 30 дней: 1. Имя (балл), 2. …, 3. …».

## 6. Недельный дайджест

- Настройка `weekly_digest_time` в `settings` (по умолчанию `09:00`), редактируется в админке.
- Шаг планировщика `weeklyDigest`: если сейчас понедельник по `TZ`, локальное время ≥ настройки и `settings.weekly_digest_sent_for` ≠ дата этого понедельника → отправить владельцу и записать дату. Пропущенный понедельник (сервер лежал) не догоняется, если уже вторник.
- Текст: «Итоги недели <дата–дата>: задания выдано A, в срок B, поздно C, просрочено D; тесты сдано E, провалено F; курсов завершено G. Рейтинг за 30 дней:» и список «место. Имя: балл (в срок X из Y, тесты Z)», сотрудники без данных в конце.
- Если владелец не привязан, шаг ничего не делает и не помечает отправку.

## 7. Тестирование

- `server/stats`: сценарии на in-memory SQLite: в срок / поздно / просрочено, незавершённые не считаются, границы периода по `due_at`, пересдачи (последняя попытка), отсутствие данных, формула балла в трёх режимах, ничьи в рейтинге, сводка сегодня/неделя с локальной полуночью по `TZ`.
- API: inject на все ручки, 401 без сессии, валидация `days` и времени дайджеста.
- Бот: «Мой рейтинг» для сотрудника с данными и без, «Сводка» владельца с топ-3.
- Планировщик: дайджест отправляется один раз в понедельник после заданного времени, не отправляется во вторник за пропущенный, не отправляется без владельца.
- Ручной прогон: сводка и карточка в админке на накопленных данных, «Мой рейтинг» в боте.
